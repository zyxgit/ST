# 后续演进路线图

路线图只记录未来计划、优先级和验收方向；已完成能力见 `docs/status/README.md`。

## 执行原则

- 不要一次性要求 AI “完成一个阶段”。必须拆成可独立评审的小任务。
- 每个任务必须有明确范围、禁止范围、验收标准和文档同步要求。
- 高并发、事务、权限、安全相关任务必须先做方案评审。
- AI 对需求合理性或实现方向不确定时必须先提问。

## 阶段一：订单 Saga 与可靠消息样板增强

当前核心链路已具备，后续可增强：

- 消息重放后台管理页面。
- Saga 可视化查询和补偿操作。
- RabbitMQ TTL/DLX 延迟关单替代或补充后台扫描。
- 更完整的集成测试和 k6 压测报告。

## 阶段二：高并发网关与权限缓存

建议拆票：

1. 网关限流规则管理化。
2. Redis 限流监控指标。
3. Identity 权限缓存与变更失效。
4. 租户级限流和配额拦截器。

验收：限流策略可配置、可观测、可回滚；权限变更后缓存能及时失效。

## 阶段三：文件中心增强

建议拆票：

1. 分片上传清理任务。
2. 对象存储实现（S3/MinIO 等）。
3. 文件病毒扫描或内容校验扩展点。
4. 大文件下载限速与签名 URL 安全增强。

验收：大文件上传可恢复、可清理、可迁移存储后端。

## 阶段四：SaaS 能力深化

建议拆票：

1. 租户切换与租户上下文统一。
2. EF 全局过滤器审计。
3. 租户套餐与配额拦截。
4. 租户级缓存键空间和限流。
5. 租户级数据导出和归档。

验收：租户数据隔离、权限隔离、资源配额可验证。

## 阶段五：可观测性深化

建议拆票：

1. Tempo Trace 接入。
2. Grafana Dashboard 模板。
3. 业务指标：订单成功率、库存冻结失败率、支付失败率、Outbox 积压量。
4. 告警规则和演练文档。

验收：能从用户请求追踪到跨服务事件处理，能发现积压和失败。
